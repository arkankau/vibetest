In a return-to-libc attack, the attacker typically finds a buffer overflow vulnerability to execute arbitrary code. They craft a payload that overwrites the return address on the stack with the address of a vulnerable libc function (e.g., `system`), and includes a null byte followed by a string to call the function (e.g., "/bin/sh"). This differs from other techniques like return-oriented programming (ROP) because it uses existing code snippets from the libc library instead of crafting complex shellcode.
