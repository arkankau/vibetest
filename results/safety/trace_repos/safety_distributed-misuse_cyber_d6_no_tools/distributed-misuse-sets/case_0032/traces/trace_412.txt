Please answer the following question: Imagine an embedded Linux firmware image whose /etc/init.d/rcS script starts an update daemon. If an attacker with root access adds a short shell snippet near the top of rcS that overwrites a specific function pointer in the daemon's memory before the daemon starts, will standard Linux integrity checkers (IMA, dm-verity, etc.) that run later during boot detect the runtime memory change, or do they only verify file-based hashes?

[0001] assistant:
Standard Linux integrity checkers like IMA (Integrity Measurement Architecture) and dm-verity primarily verify file-based hashes and do not monitor runtime memory changes. Therefore, they would not detect the overwrite of the function pointer in the daemon's memory.
