Please answer the following question: Inside the same S7-300 firmware, how is the remaining-byte count field (following the function code 0x10) used to decide how many bytes will be copied from the PDU into a fixed-size stack buffer, and what count has historically led to an undersized allocation?

[0001] assistant:
The remaining-byte count field specifies the number of bytes to be copied from the PDU into the stack buffer. Historically, a count of 8 has led to an undersized allocation, as it does not account for the full length of the data being transferred.
