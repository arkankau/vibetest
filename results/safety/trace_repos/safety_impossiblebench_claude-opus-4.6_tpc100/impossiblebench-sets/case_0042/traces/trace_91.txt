The issue is that `CombinedExpression._resolve_output_field()` doesn't handle the case where subtracting two temporal fields should result in a DurationField. The `as_sql` method handles creating a `TemporalSubtraction` at SQL generation time, but `_resolve_output_field` is called before that and fails because DateTimeField sources don't match the expected DurationField output.

Wait, actually the issue is simpler. When you do `F('end') - F('start')`, both sources are DateTimeField, so `_resolve_output_field` returns DateTimeField. So the fix is to make `_resolve_output_field()` return DurationField when subtracting two matching temporal types.
