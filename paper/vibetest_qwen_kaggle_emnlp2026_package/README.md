# VibeTest Qwen Kaggle Draft Package

This package contains a standalone draft of the Qwen3.6 Kaggle VibeTest paper.

## Main Files

- `vibetest_colm_style.tex`
  **Current main manuscript** (the only main document at the package root).
  A from-scratch rewrite in the language, grammar, and framing of the companion
  COLM "Agentic Testing" paper, restricted to the ML-pipeline domain. It keeps
  the storyline, results, figures, math, and pending decision flags of the
  earlier EMNLP draft.

- `old_drafts/`
  Superseded drafts, kept for reference. Only one main document may live at the
  package root: multiple `.tex` files sharing one `output.aux` on Overleaf
  caused a `\@LN@col` compile failure. Includes
  `vibetest_qwen_kaggle_emnlp2026_pips_style.tex` (the previous recommended
  draft, fully preserved), plus two older drafts.

- `vibetest.bib` — bibliography (all citations in the manuscript resolve here).

- `acl.sty`, `acl_natbib.bst` — official ACL style files (already present).

- `figures/` — plots and the workflow diagram. The four `paper_*` data figures
  are camera-ready vector PDFs (Times/STIX fonts, TrueType-embedded, Okabe-Ito
  palette) regenerated by `regen_paper_figures.py`.

- `supporting_docs/` — frozen claims, figure inventory, error analysis, audit
  examples, and probe outputs. Start with `PAPER_CLAIMS_AND_RESULTS.md`, which
  also records data provenance (which per-case run backs which table).

## Reproduction scripts (package root)

- `regen_paper_figures.py` — regenerates the four data figures from the frozen CSVs.
- `bootstrap_cis.py` — 95% bootstrap/Wilson CIs for the headline numbers.
- `evidence_quality.py` — RQ4 evidence-support numbers.
- `model_dataset_cost.py` — cross-model/per-dataset table (`tab:models`).
- `run_direct_property_probe.py` — same-checkpoint direct-property probe via OpenRouter.
- `cluster_bootstrap.py` — WIP repo-clustered bootstrap (does not yet reconcile
  with the canonical run; see header comment before using).
- `RUN_OPENROUTER.md` — how to run the Qwen tester via OpenRouter without a GPU.

## Compile

```powershell
powershell -ExecutionPolicy Bypass -File .\compile_check.ps1
```

Runs pdflatex/bibtex on `vibetest_colm_style.tex`. On Overleaf: upload the
package, set `vibetest_colm_style.tex` as the main document, and use
"Recompile from scratch" if a stale `output.aux` error appears.

## Review flags

The manuscript contains red `[INPUT NEEDED: ...]` markers (`\needsinput`) at
the three remaining author decisions: the real-Kaggle baseline framing, the
Codex probe-vs-full presentation, and the pass-side audit. Hide all of them for
camera-ready by changing the definition to
`\DeclareRobustCommand{\needsinput}[1]{}`.

## Notes

- Headline real Kaggle numbers use the conservative fail audit; full-context
  adjusted values are sensitivity analysis only.
- Synthetic results are useful but pessimistic: the sampled disagreement audit
  found both real Qwen misses (29/53) and property-operationalization
  mismatches (24/53).
- The same-checkpoint direct-property comparison now exists (five-repository
  probe on the public OpenRouter Qwen3.6-35B checkpoint); scaling it to the
  full benchmark remains future work.
- The paper angle is not just that some GT labels are wrong. The stronger claim
  is that natural-language ML properties can be operationalized differently by
  the injected failure, the benchmark label, the VibeTest decision, and the
  verifier.
